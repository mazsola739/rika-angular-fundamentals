Components are the main building block for Angular applications. Each component consists of:

  • An HTML template that declares what renders on the page
  • A Typescript class that defines behavior
  • A CSS selector that defines how the component is used in a template
  • Optionally, CSS styles applied to the template

You define a component's application logic — what it does to support the view inside a class. The class interacts with the view through an API of properties and methods.

For example, ListItemsComponent has a items property that holds an array of items. Its selectItem() method sets a selectedItem property when the user clicks to choose a item from that list.

src/app/list-items.component.ts (metadata)

@Component({
 selector: "app-list-items",
 templateUrl: "./list-items.component.html",
 styleUrls: "./list-items.component.css",
})
export class ListItemsComponent {
 items: Item[] = [
   { id: 1, name: "item1" },
   { id: 2, name: "item2" },
   { id: 3, name: "item3" },
 ];
 selectedItem: Item;

 selectItem(item: Item) {
   this.selectedItem = item;
   alert(`item id: ${item.id}, item name: ${item.name}`);
 }
}

Component metadata

The @Component decorator identifies the class immediately below it as a component class, and specifies its metadata. In the example code above, you can see that ListItemsComponent is just a class, with no special Angular notation or syntax at all. It's not a component until you mark it as one with the @Component decorator.

The metadata for a component tells Angular where to get the major building blocks that it needs to create and present the component and its view. In particular, it associates a template with the component, either directly with inline code, or by reference. Together, the component and its template describe a view.

In addition to containing or pointing to the template, the @Component metadata configures, for example, how the component can be referenced in HTML and what services it requires.

This example shows some of the most useful @Component configuration options:

  • selector: A CSS selector that tells Angular to create and insert an instance of this component wherever it finds the corresponding tag in template HTML. For example, if an application's HTML contains <app-list-items></app-list-items>, then Angular inserts an instance of the ListItemsComponent view between those tags.
  • templateUrl: The module-relative address of this component's HTML template. Alternatively, you can provide the HTML template inline, as the value of the template property. This template defines the component's host view.

Templates and views

You define a component's view with its companion template. A template is a form of HTML that tells Angular how to render the component.

Views are typically arranged hierarchically, allowing you to modify or show and hide entire UI sections or pages as a unit. The template immediately associated with a component defines that component's host view. The component can also define a view hierarchy, which contains embedded views, hosted by other components.

A view hierarchy can include views from components in the same NgModule, but it also can (and often does) include views from components that are defined in different NgModules.

Template syntax

A template looks like regular HTML, except that it also contains Angular template syntax, which alters the HTML based on your application's logic and the state of application and DOM data. Your template can use data binding to coordinate the application and DOM data, pipes to transform data before it is displayed, and directives to apply application logic to what gets displayed.

For example, here is a template for the ListItemsComponent:

src/app/list-items.component.html

<h2>Items List</h2>

<p>
 <em>Select an item from the list to see details.</em>
</p>

<div *ngFor="let value of items">
 <button type="button" (click)="selectItem(value)">{{ value.name }}</button>
</div>

This template uses typical HTML elements like <h2> and <p>, and also includes Angular template-syntax elements, *ngFor, {{item.name}} and (click). The template-syntax elements tell Angular how to render the HTML to the screen, using program logic and data.

  • The *ngFor directive tells Angular to iterate over a list.
  • {{item.name}} and (click) bind program data to and from the DOM, responding to user input.
